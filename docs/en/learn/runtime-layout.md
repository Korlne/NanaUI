# Layout engine internals: `RuntimeLayoutEngine`

This chapter takes apart the layout engine in `nana-ui-runtime`: how computed styles enter measurement, how containers choose a formatting context, what mechanism lets incremental layout "relayout only the affected subtrees", how text measurement and box layout converge through feedback, and why a scroll offset never rewrites layout boxes. After reading it you will understand: the complete path of one incremental pass of `layout_document_with_frontier`; the `LayoutFrontier` dependency graph and the propagation rules for each kind of invalidation seed; the division of labor between the two output contracts `IntrinsicMetrics` and `LayoutResult`; and the exact invalidation scope triggered by viewport resize, text wrapping feedback, and scrolling.

## Responsibilities and boundaries

- **Stateless algorithm owner + cross-frame retained cache**: `RuntimeLayoutEngine` itself is a zero-field unit struct (`#[derive(Default, Clone, Copy)]`, `crates/nana-ui-runtime/src/layout_engine.rs:88-89`). It consumes the resolved `LayoutStyle` and text shaping metrics in `UiWorld` and produces an atomic layout write-back. All cross-frame state lives in the per-document `RetainedLayoutCache` (`layout_engine.rs:719`).
- **Input boundary**: Runtime does not parse CSS. What enters the layout engine is Style Model data (`nana_ui_core::LayoutStyle`, attached to `NodeRecord.resolved_layout`).
- **Output boundary**: the canonical geometry authority for painting, hit testing, accessibility, and scrolling is the immutable `LayoutResult` (`crates/nana-ui-runtime/src/layout_result.rs:113`, Issue #203). The `LayoutBox` on a node is only a compatibility projection of its `bounds`.
- **Write-back through `MutationQueue`**: the layout engine does not bypass the world to tamper with the node table directly. It enqueues `MutationQueue::write_layout` only for boxes whose geometry actually changed, and publishes `LayoutResult` in one step after the whole batch is committed.

## Internal structure

### 1. Style resolution and formatting context selection

`UiWorld::resolve_style` (`crates/nana-ui-runtime/src/world/style.rs:87`) resolves computed styles top-down from the root. A child with no local overrides shares its parent's `Arc<ComputedStyle>` directly (`publish_inherited_computed_style`, `:12`). The layout engine reads `motion_layout(id, &resolved_layout)` (`:106-108`), which folds in the responsive container bucket and Layout-class animations.

The formatting context is decided in one place, `establish_context` (`crates/nana-ui-runtime/src/layout_engine/context.rs:29`): `Grid` → `Flex` → `Inline` (in-flow children include inline-level elements) → `Flow`. Both the measure and placement phases call the same function, so the same container can never get two different algorithms. The per-context solvers are split by module:

- **Flow collection (`flow.rs:23`)**: `collect_flow_children_reporting` collects the in-flow child list and explicitly reports whether it depends on deeper descendants because of `display: contents` or inline boxes nested inside blocks.
- **Flexbox (`flex.rs:25`)**: `distribute_flex_main` performs main-axis space distribution and cross-axis stretching.
- **Grid (`grid.rs:23`)**: `Grid2DLayout` solves two-dimensional explicit tracks and `subgrid` (`InheritedGridTracks`, `:16`).
- **Inline wrap packing (`inline.rs:6`)**: `pack_wrap_lines` handles line wrapping of inline-level atomic boxes.
- **Dynamic adaptive layout (`dynamic.rs:1-18`, Issues #209/#212/#213)**: when a container configured with `AdaptationProfile::solve_overflow` runs out of space on a single line, it uses `DynamicPass::envelope` and `solve_deficit` to borrow space from flexible children in order of increasing cost. The envelope (`RetainedEnvelope`) is retained and reused across resizes.

### 2. Two-phase traversal and three cross-frame cache layers (`intrinsic_size` → `place_node`)

Each layout pass consists of bottom-up **intrinsic measurement (`intrinsic_size`, `measure.rs:6`)** and top-down **node placement (`place_node`, `placement.rs:6`)**. `RetainedLayoutCache` (isolated per document) avoids recomputation with three cache layers:

1. **Intrinsic fact cache shared across contexts (`intrinsic_cache.rs:1-13`)**: the cache key contains only the subtree's content/style identity and the **constraint class**, not the formatting context type of the outer container. So whether a Flex, Grid, or Block parent asks for the intrinsic size of the same subtree, it hits the same cache entry.
2. **Container placement plans (`ContainerPlan`) and measure plans (`MeasurePlan`)**: `place_node` replays the cached container plan and uses `PlanCheck` (`placement.rs:33-43`) to decide `Unchanged` (skip), `ChangedFrom(idx)` (replay from the first changed child), or `Stale` (full recompute). Container plans follow **Gate E (one plan per container; repeated edits replace in place rather than append, `layout_engine.rs:454-458`)**. Measure plans are **merged rather than overwritten** per `(container, constraint slot)` (because the same container is often measured under both main-axis and cross-axis constraints in one pass, `:480-491`), and slots not measured in this pass are actively checked with `plan_missed_change` (`:493-509`).
3. **Same-source full snapshot pass-through**: if a full layout is requested but neither `layout_source_epoch` nor the viewport has changed, the previous output snapshot is returned whole (`:214-246`).

### 3. Incremental frontier: `LayoutDependencyGraph` and `LayoutFrontier`

The incremental entry point `layout_document_with_frontier` (`layout_engine.rs:150`) does not crudely "spread a dirty node all the way to the document root". It propagates through a dependency graph weighted by dependency footprint (`LayoutDependencyFootprint`):

- `LayoutDependencyGraph` (`layout_frontier.rs:61`) maintains bidirectional parent-child edges (`add_parent_dependency_split` accounts upward metric dependencies and downward constraint dependencies separately, so a seed that affects only position, `placement-only`, does not drag the whole ancestor chain into remeasurement, `:103-116`), same-context sibling edges (Flex lines / Grid tracks, `:120`), and layout isolation boundaries (`:140`).
- Invalidation keeps spreading outward only when a child's output change (classified by `LayoutResult::metric_delta` as `INTRINSIC_INLINE/BLOCK`, `BASELINE`, `USED_SIZE`, `PLACEMENT`, `layout_result.rs:205`) hits a footprint that the parent edge actually declares it consumes.
- **Exact seeding on viewport resize**: each box records the viewport axes it actually read in `viewport_basis` (`vw` records only width, `vh` only height, `position: fixed` both axes, an ordinary box `0`, `layout_engine.rs:64-77`). When the window changes only its height, `UiWorld::viewport_resize_seeds` (`world.rs:3800`) does not pull subtrees that use only `vw` or do not depend on viewport height into relayout.

### 4. Text measurement feedback loop and scroll extent model

Once layout settles a container's width, it may change how multi-line text wraps, which in turn changes the container's height. `RuntimeDocument::flush` limits this "layout → scoped reshape → layout again" feedback loop to at most `POST_LAYOUT_SHAPE_PASSES = 4` rounds (`runtime_document.rs:48`), and converges as soon as no new layout seeds are produced.

For scroll containers (`world/scroll_bounds.rs:1-4`): **the scrollable content range (scroll extent) is a pure layout product (the union of descendant boxes aggregated by the `MaxTree` segment tree in $O(n)$), while the scroll offset (`scroll_offset`) is a paint and hit-test transform**. Calling `scroll_to_clamped` (`world/mutation.rs:2758`) updates only `NodeRecord.scroll_offset` and the hit index scroll offset, and marks `DirtyMask::INPUT | DirtyMask::RENDER`. **It never rewrites descendants' `LayoutBox` or `LayoutResult`**.

## Collaboration and data flow

```text
commit (SetStyle / Insert / …) ──generates──▶ LayoutFrontierSeed (typed invalidation seeds)
RuntimeDocument::flush ──calls──▶ AppContext::layout_document_with_frontier
    ├─ merge pending seeds + (if the viewport changed) add viewport_resize_seeds
    ├─ compute the LayoutFrontier by footprint closure along the LayoutDependencyGraph
    ├─ intrinsic_size (hit intrinsic cache / merge measure plans) → place_node_scoped (replay container plans)
    ├─ enqueue write_layout only for boxes whose geometry changed → commit → publish_layout_results
    └─ scoped text reshape feedback (≤ 4 rounds, converges when no new seeds)
Output: immutable LayoutResult (consumed jointly by Scene extraction, hit testing, accessibility, and scrolling)
```

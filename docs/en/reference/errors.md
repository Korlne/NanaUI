# Reactive and View Diagnostic Codes

The table below lists the runtime faults you may hit while writing declarative views and reactive state. For the diagnostics buffering mechanism, the `.nlog` format, and why file I/O is forbidden on frame paths, see [Diagnostics and Application Paths](diagnostics.md).

| Fault code (Descriptor Name) | Trigger | Fix |
| --- | --- | --- |
| `runtime.reactive.disposed_access` | A signal owned by a scope (such as a list row or a conditional branch) is read or written after that scope has been disposed (this also panics; the message includes the source location where the signal was created). | Do not let signals created inside an `each` row or a `when` branch leak out and be held long term. In async callbacks or deferred cleanup tasks, use `try_update` / `try_set_if_changed` instead (they write only while the signal is alive and safely return `false` once it is disposed). See [Mount and Unmount](../guide/essentials/lifecycle.md). |
| `runtime.reactive.did_not_settle` | Reactive effects (`watch_effect`) trigger each other in a cycle and fail to converge after more than 64 consecutive rounds (the remaining pending queue is dropped to prevent a deadlock). | Do not unconditionally write, inside a `watch_effect`, the same signal that effect reads. To derive a new value, use `computed`, or use `set_if_changed` to cut off writes of an equal value. See [Watchers](../guide/essentials/watch.md). |
| `runtime.reactive.static_deps_mismatch` | In debug builds, a binding whose dependency list was declared by the `.vue` compiler's static analysis reads, at run time, a signal outside that static declaration (the error includes the template line and column; release builds skip this check). | Make sure every signal a template expression reads appears explicitly in a scope the compiler can see. Do not read signals implicitly inside ordinary opaque functions that the template calls. See [The .vue Dialect](../guide/scaling/sfc.md). |
| `runtime.view.error_unhandled` | A view-building closure returns `Err`, but no enclosing `error_boundary` catches it. | Wrap the view in an `error_boundary` (or `<ErrorBoundary>`) higher up to provide a fallback UI, or handle the error inside the view. See [Declarative Views](reactive-view.md). |

Besides these fault codes, the `runtime.reactive` domain provides a set of zero-I/O atomic counter and histogram metrics for observing reactive system load: `runtime.reactive.flushes`, `runtime.reactive.signal_writes`, `runtime.reactive.effects_run`, `runtime.reactive.nodes_patched`, `runtime.reactive.commits`, and the duration histogram `runtime.reactive.flush`.
